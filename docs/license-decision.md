# 许可证选型记录（内部文档，非面向使用者）

> 本文记录「为什么选 GPLv3」，供维护者决策参考。README 里只保留结论，不放这些权衡。

## 需求

1. 别人拿去二次修改、再分发，必须**同样开源**；
2. 无论怎么改，都要**保留原作者署名**。

## 候选对比

| | MIT | GPLv3（采用）| CC BY-SA 4.0 |
|---|---|---|---|
| 商用 | 可以 | 可以 | 可以 |
| 修改后闭源分发 | 可以 | **不可以** | 不可以（仅限文本）|
| 保留署名 | 需保留版权声明 | 需保留版权声明**并标明修改** | 需署名 |
| 专利 | 未涉及 | 贡献者授予专利许可，专利诉讼则终止 | 未涉及 |
| 分发二进制 | 无要求 | 必须提供对应源代码 | 不适用 |
| 官方中文译本 | 无 | **无**（本仓库自写要点对照）| **有**（CC 官方简体中文）|
| 适用对象 | 代码通用 | 代码通用 | 更适合文档/文本 |

## 结论

- **主许可证用 GPLv3**：同时满足「衍生必须开源」与「保留署名」，且覆盖脚本与译文，不必维护双许可。
- **不用 MIT**：不满足"必须开源"这一条。
- **不用 AGPLv3**：本项目是本地工具，不存在网络服务场景，AGPL 的额外条款没有意义。
- **译文不单独用 CC BY-SA 4.0**：虽然它有官方中文译本（对我们这种"中英对照"诉求更友好），
  但代码与译文分属两个许可证会让使用者难以判断边界，收益不抵复杂度。
  若将来把译文拆成独立仓库，可以再考虑 CC BY-SA 4.0。
